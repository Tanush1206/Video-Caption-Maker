# Code style

The conventions this codebase **actually follows**, drawn from the code
itself. When adding code, match the surrounding file. Where a convention isn't
enforced by a tool, this doc says so.

## 1. General

- **Comments explain *why*, not *what*.** The codebase's defining habit is a
  docstring or comment that records the reason for a choice, often with the
  measurement behind it. Examples:
  - the large-v3 vs medium table in `backend/app/config.py`;
  - "why VAD is off" in the same file;
  - "why ARG VERSION is last" in `backend/Dockerfile`.
  
  Do this for any non-obvious choice. Don't narrate obvious code.
- **Name the trap you avoided** when a simpler-looking alternative is wrong.
  For example, `buttonVariants` lives outside `"use client"` (and
  `button-variants.ts` explains why), and `PurePosixPath` is used for stored
  paths.
- **User-facing text is a sentence that says what happened and what to do**,
  never an exception string or a status code. See `friendly_error` in
  `backend/app/workers/transcription.py`, `extractError` in
  `frontend/src/lib/api.ts`, and the "Couldn't …" messages in the installers.
- **One source of truth.** Lists the client needs (languages, fonts, presets,
  model choices, resolutions) are **served by the API**, not copied into the
  frontend (ARCHITECTURE.md §11).
- **Minimal changes.** Fix what was asked; don't reformat or rename
  unrelated code.

## 2. Python (backend)

### Layout and naming
- **Package layout:** `app/api` (routers), `app/schemas` (Pydantic),
  `app/models` (ORM, one table per file), `app/services` (logic),
  `app/workers` (Celery), `app/utils`. Files and functions are
  `snake_case`; classes `PascalCase`; module constants `UPPER_SNAKE` with a
  comment saying where the number came from (`MAX_REQUEUES = 3`,
  `MAX_DISTANCE = 0.75`, `MIN_VRAM_GB_FOR_LARGE = 6.0`).
- **Service functions** are verbs on a resource: `get_owned_video`,
  `create_export`, `list_captions`, `mark_queued`, `delete_video`.
  - Ownership is checked in the query (`get_owned_*` joins to the owner), not
    after loading.
- **Routers** use `APIRouter()`. Each file has private helpers such as
  `_require_owned` and `_to_read`, which are deliberately not shared until a
  third router needs them (comment in `caption_styles.py`).
- **Every module starts with a docstring** stating its job and its key
  constraint.

### Typing and data
- Type hints everywhere: `X | None` (not `Optional`), `list[int]`,
  `collections.abc.Callable`.
- SQLAlchemy 2.0 style: `Mapped[...]` and `mapped_column(...)`, async
  sessions.
- Enums are `str, enum.Enum` and stored by value (`values_callable`).
- FastAPI dependencies use the `Annotated` shorthands from
  `app/dependencies.py`: `user: CurrentUser, db: DbSession`.
- Pydantic v2 schemas: `model_dump(exclude_unset=True)` for PATCH, so
  "absent" and `null` stay different (`api/captions.py`).
- Media times are **integer milliseconds** (`*_ms`); convert Whisper's float
  seconds once.
- Settings only through `get_settings()` (`app/config.py`). **Never**
  `os.environ` in `app/`.

### Error handling
- **Routes** raise `HTTPException(status_code=status.HTTP_…, detail="Sentence.")`:
  - **404, never 403**, for resources the user doesn't own;
  - **409** for state conflicts;
  - **422** for semantic validation.
- **Degrade, don't fail**, when the main result still stands:
  - indexing, re-index queuing and translation failures are logged and
    swallowed;
  - the video still completes, with a `notice` if the user should know.
- **Deliberately broad excepts** carry `# noqa: BLE001` and a comment giving
  the reason (`utils/rate_limit.py`, `workers/celery_app.py`).
- **Worker failures** become `status=failed` with a `friendly_error`
  sentence, and the exception is re-raised for Celery. A stuck `processing`
  row is worse than an honest failure.
- **Never** leave partial files behind. Unlink on failure
  (`_stream_to_disk`), and write-then-rename caches (`get_waveform`).

### Logging
- `logger = logging.getLogger(__name__)` per module (`log` in `api/fonts.py`).
- Use `logger.info` for pipeline milestones, `warning` for fallbacks and
  `error`/`exception` for failures. Use `%s` formatting, not f-strings, in log
  calls.
- **Never log secrets or request bodies.** `app_settings.py` logs no values;
  `audit.log` stores no bodies.
- `httpx` is turned down to WARNING in `main.py` and `celery_app.py`.

### Imports
- Heavy ML imports (`faster_whisper`, `ctranslate2`, `sentence_transformers`,
  `google.genai`) go **inside functions**, so the API process stays light.
  Worker tasks are imported lazily inside the route function that queues them.

### Formatting and lint
- 4-space indent, double quotes, lines generally ≤ 100 characters. Alembic's
  autogenerated headers keep single quotes.
- **No formatter or ruff config is committed.** `ruff` is installed in the
  dev image (`pip install … ruff` in the `dev` stage) and can be run by hand:
  ```bash
  docker compose exec backend ruff check app tests
  ```
  CI does not run it (see Open questions).

### Tests
- `backend/tests/test_<area>.py`. Test names are **sentences of the behaviour**:
  `test_another_user_cannot_reach_your_video`,
  `test_a_job_that_keeps_crashing_the_worker_is_failed_not_requeued_forever`.
- Use realistic fixtures: a real FFmpeg-generated MP4, not random bytes.
- Network tests are marked `@pytest.mark.network`.

## 3. TypeScript / React (frontend)

### Layout and naming
- **Files are `kebab-case`** (`video-library.tsx`, `use-videos.ts`).
  Components are `PascalCase` **named exports**. The only default exports are
  Next's `page.tsx`, `layout.tsx`, `error.tsx` and `not-found.tsx`.
- **Folders:**
  - `src/app` (routes only);
  - `src/components/<feature>/` (feature UI);
  - `src/components/ui/` (primitives);
  - `src/hooks/use-<resource>.ts` (TanStack Query);
  - `src/lib/` (non-React helpers);
  - `src/types/<resource>.ts` (API types);
  - `src/stores/` (Zustand).
- **Imports** use the `@/` alias (`tsconfig.json` paths).
- **API types mirror the backend schemas, field for field, in `snake_case`**
  (`types/video.ts`: `caption_language`, `stage_detail`). Don't camelCase
  them.

### React patterns
- `"use client"` only where needed. Modules that export **values** for
  server components (`button-variants.ts`, `lib/theme.ts`) must **not** have
  it.
- **Data access goes through hooks.** Query keys come from a per-resource
  factory (`streamKeys`, `exportKeys`). Poll with `refetchInterval` **only
  while something is busy**, and return `false` otherwise.
- **HTTP goes through `api`** in `src/lib/api.ts`, which provides:
  - the bearer header;
  - one shared refresh on a 401, then a single replay;
  - `ApiError(status, sentence)`.
- **Classes are composed with `cn()`** from `src/lib/utils.ts` (clsx +
  tailwind-merge, with the type scale registered). Variants use `cva`.
- **No mock data.** Every figure rendered comes from the API.
- **Comments are JSDoc blocks** above components and hooks, explaining why.

### Styling
- Use Tailwind utilities and design tokens only; see
  [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).
  - No hex colours or `indigo-*`/`slate-*` utilities in components.
  - No inline `style` except for computed values (for example `--fill`).

### Lint, type-check, build

```bash
# in the dev stack
docker compose exec frontend npm run lint        # next lint, config: next/core-web-vitals
docker compose exec frontend npm run type-check  # tsc --noEmit (strict)

# production build: never inside the running dev container (it clobbers .next);
# CI runs it, or build the image target:
docker build --target build frontend
```

- **No Prettier config is committed.** Formatting is by convention: 2-space
  indent, double quotes, semicolons, trailing commas where multiline.
- `npm run lint`, `type-check` and `build` run in CI on every push and PR
  (`.github/workflows/ci.yml`).

## 4. Shell and PowerShell (installer)

- **Bash:** `set -euo pipefail`; small helpers (`ok`, `warn`, `die`); check
  `docker` exit codes explicitly. It must pass `bash -n` and
  `shellcheck -S warning` (CI).
- **PowerShell 5.1:**
  - use `$ErrorActionPreference = 'Continue'` and check `$LASTEXITCODE` after
    each native command, because under `Stop` Docker's stderr progress
    becomes a terminating error;
  - wrap the installer in `& { … }` and `throw`, never `exit`, since it runs
    via `iex`.
- **Line endings** (`.gitattributes`): `*.sh` and `install/vcm` must be LF,
  and `*.ps1` CRLF.
- **Every download is checked against `SHA256SUMS` before anything is
  replaced.**

## 5. Commit messages

The history follows **Conventional Commits**: `type(scope): summary`.

- **Types in use:** `feat`, `fix`, `docs`, `style` (UI restyles), `build`
  (Dockerfiles, compose), `ci`, `test`, `chore`, `refactor`, `assets`.
- **Scopes in use:** `api`, `worker`, `ui`, `web`, `install`, `vcm`,
  `models`, `transcription`, `translation`, `captions`, `exports`,
  `render`, `progress`, `a11y`, `settings`, `flow`, `editor`, `fonts` and
  others. A scope is optional (`docs: …`, `build: …`).
- **The summary** is lowercase and says what changed in user terms. Examples
  from the log:
  - `fix(worker): give up on a job after 3 automatic requeues`;
  - `fix(api): the allowed origin is the install's own address and port`;
  - `build: a new version no longer re-downloads the whole image`.
- **Small commits:** about 5 files at most, one fix or one screen per commit.
- **No `Co-Authored-By` trailers.**
- **Never commit** `.env`, certificates, storage, dumps, `design/stitch/` or
  `learning-guide.md` (all gitignored).

## 6. Do / don't

| Do | Don't |
|---|---|
| Read the relevant doc in `docs/` before changing code | Rewrite a module to fix one bug |
| Put logic in `services/`, keep routers thin | Put business logic in a router |
| Return 404 for someone else's resource | Return 403 and confirm the ID exists |
| Generate filenames (UUID); keep the user's name as a label | Build a path from user input |
| Store media times as integer ms | Compare float seconds |
| Degrade with a `notice` when the main result stands | Fail a transcription because indexing or translation failed |
| Write progress in its own short DB session | Write progress through the long-running job's transaction |
| Load heavy ML libraries lazily, unload one model before loading the other | Import faster-whisper/torch at module level in the API |
| Serve option lists from the API | Hard-code languages, fonts or models in the client |
| Use `ui/` primitives and tokens | Hand-roll buttons or hard-code colours |
| Add new type-scale keys to `extendTailwindMerge` too | Use the `hidden` attribute on an element with a display utility |
| Run `npm run type-check` against the dev container | Run `next build` inside the dev container |
| Put new version metadata **last** in a Dockerfile stage | Declare an `ARG` used only for labels at the top of a stage |
| Delete only named test Docker resources | `docker system prune` (or any host-wide prune) on a shared host |
